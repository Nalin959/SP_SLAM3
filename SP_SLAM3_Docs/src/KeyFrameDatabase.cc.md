# Documentation: `KeyFrameDatabase.cc`

## High-Level Overview
The `KeyFrameDatabase.cc` file implements the `KeyFrameDatabase` class, which serves as the global search engine for the SLAM system. It enables instantaneous Place Recognition—allowing the system to realize it has returned to a previously visited location (Loop Closure) or to recover its position after tracking is completely lost (Relocalization).
It achieves this using an **Inverted Index** (similar to how Google indexes the internet) based on Bag-of-Words (BoW) generated by DBoW2/DBoW3. Instead of comparing a new frame against every past KeyFrame in history (which would take $O(N)$ time and scale horribly), the database queries visual "words" in $O(1)$ time to instantly find candidate matches.

**Primary Dependencies:**
- `KeyFrameDatabase.h`, `KeyFrame.h`
- DBoW3 (`BowVector.h`) for the inverted file structure.
- Threading (`std::mutex`, `std::unique_lock`) because Loop Closing, Relocalization, and Map Merging all query this database concurrently.

## Block-by-Block Breakdown

### 1. Inverted File Architecture

```cpp
KeyFrameDatabase::KeyFrameDatabase (const ORBVocabulary &voc): mpVoc(&voc)
{
    mvInvertedFile.resize(voc.size());
}

void KeyFrameDatabase::add(KeyFrame *pKF)
{
    unique_lock<mutex> lock(mMutex);
    for(DBoW3::BowVector::const_iterator vit= pKF->mBowVec.begin(), vend=pKF->mBowVec.end(); vit!=vend; vit++)
        mvInvertedFile[vit->first].push_back(pKF);
}
```
**Explanation:** 
- The vocabulary contains roughly 1 million visual "words" (pre-trained clusters of ORB features).
- `mvInvertedFile` is an array where the index is the Word ID, and the value is a `std::list<KeyFrame*>` containing every KeyFrame that observed that specific word.
- When `add()` is called, it iterates through the sparse BoW vector of the new `KeyFrame` and appends the KeyFrame to the inverted list for each word.

### 3. Relocalization 

```cpp
vector<KeyFrame*> KeyFrameDatabase::DetectRelocalizationCandidates(Frame *F, Map* pMap)
```
**Explanation:** 
- Identical in algorithmic logic to `DetectCandidates`, but executed by the Tracking thread when the camera becomes "LOST" (e.g., due to a sudden blur or occlusion).
- Instead of taking a `KeyFrame*` as the query, it takes a transient `Frame*`. It rapidly returns a list of historical KeyFrames that the lost camera might currently be looking at, allowing the Tracking thread to attempt feature matching and recover its pose.
