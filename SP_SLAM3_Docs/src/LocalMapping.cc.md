# Documentation: `LocalMapping.cc`

## High-Level Overview
The `LocalMapping.cc` file implements the `LocalMapping` class, which serves as the map-building core of the SLAM system. It runs in its own dedicated background thread. 
While the **Tracking Thread** operates at camera speed (~30Hz) to rapidly estimate the immediate pose, the **Local Mapping Thread** takes the `KeyFrames` generated by Tracking, inserts them into the global `Atlas`, triangulates new 3D points, culls redundant data, and heavily optimizes the local trajectory using **Local Bundle Adjustment (LBA)**. 
Additionally, for Visual-Inertial setups, it is responsible for the complex task of dynamically initializing and refining the IMU biases, gravity vector, and scale.

**Primary Dependencies:**
- `LocalMapping.h`, `LoopClosing.h`, `SPmatcher.h` (LightGlue/SuperPoint), `Optimizer.h`
- Threading (`std::mutex`, `std::unique_lock`) for safe map access.

## Block-by-Block Breakdown

### 1. The Main Execution Loop (`Run()`)

```cpp
void LocalMapping::Run()
{
    while(1)
    {
        SetAcceptKeyFrames(false); // Lock Tracking thread out of inserting KFs

        if(CheckNewKeyFrames() && !mbBadImu)
        {
            ProcessNewKeyFrame();
            MapPointCulling();
            CreateNewMapPoints();
            
            if(!CheckNewKeyFrames()) SearchInNeighbors();
            
            // ... Call Optimizer::LocalBundleAdjustment or LocalInertialBA ...
            
            KeyFrameCulling();
            
            mpLoopCloser->InsertKeyFrame(mpCurrentKeyFrame);
        }
        // ... Check if Stop() is requested ...
    }
}
```
**Explanation:** 
- The master loop of the thread. It continuously polls the `mlNewKeyFrames` queue.
- **Workflow:**
  1. Blocks Tracking from passing new frames.
  2. Processes the BoW vectors.
  3. Culls bad 3D points.
  4. Triangulates new 3D points.
  5. Performs Bundle Adjustment.
  6. Culls redundant KeyFrames.
  7. Passes the optimized KeyFrame downstream to the **Loop Closing** thread.

### 4. IMU Initialization & Bundle Adjustment

```cpp

```
**Explanation:** 
- **Visual-Inertial SLAM (VI-SLAM):** The IMU cannot be used until the system successfully solves for the scale of the world (if monocular), the gravity vector, and the initial accelerometer/gyroscope biases.
- `InitializeIMU()` solves this complex non-linear problem. 
- Once initialized, it calls `Optimizer::LocalInertialBA`, which jointly optimizes the camera poses, 3D points, and IMU variables over a local sliding window of KeyFrames to minimize both visual reprojection error and IMU preintegration error.

**Explanation:** 
- As a camera stares at a static scene, or moves very slowly, it generates hundreds of KeyFrames containing redundant data. This causes the Local BA to slow down exponentially.
- This function iterates through the local window and deletes any `KeyFrame` where 90% of its MapPoints are already observed by at least 3 other KeyFrames at the same or higher scale. This ensures the map remains sparse, bounded in size, and extremely fast to optimize.
